# U Scale website

Single-page site for **U Scale**, Mehul Karotra's independent web design, development and digital marketing practice in Mumbai. Not an agency: clients contract with Mehul directly.

The site is generated by a small Python build (standard library only) into `public/`, which is what Vercel serves. Nothing generated is committed: every page, the sitemap, robots.txt and llms.txt are rebuilt on each deploy with the URL from the `SITE_URL` environment variable.

```
source/src/      page template, CSS, JS, testimonials
source/build/    build scripts, copy (work, FAQ, services, pricing), config.py (env settings)
source/static/   images and icons copied as-is (assets/, og-image.png, favicons)
public/          build output (git-ignored)
```

## Live

https://uscale.in (Vercel project `uscale`, deploys automatically on every push to `main`). Domain registered at GoDaddy; DNS: A `@` → `216.198.79.1`.

## Environment variables

| Variable | Purpose | Default |
|---|---|---|
| `SITE_URL` | Public origin used in canonical tags, Open Graph, JSON-LD, sitemap, robots.txt and llms.txt | `https://uscale.in` (`DEFAULT_SITE_URL` in `config.py`) |
| `SITE_INDEXABLE` | Force `1` (indexable) or `0` (noindex) | Indexable only when `VERCEL_ENV=production`, so preview deployments are `noindex` with a `Disallow: /` robots.txt |
| `OUTPUT_DIR` | Build output folder | `public` |
| `BUILD_DATE` | `lastmod` / `dateModified` date (YYYY-MM-DD) | Last git commit date, else today |

Set `SITE_URL` in Vercel → Project → Settings → Environment Variables (Production). See `.env.example`.

## Deploy

`vercel.json` holds everything: build command `python3 source/build/build_site.py`, output directory `public`, clean URLs, cache and security headers. Push to `main` and Vercel builds and deploys.

Other hosts (Netlify, Cloudflare Pages): same build command and output directory, and set `SITE_URL`.

## What's inside

- Hero "growth stack": five channels (Website, SEO, Social, Ads, AI search) stack into one living growth curve; it builds itself, breathes, demos switching channels off and on, and visitors can toggle each chip. Floating cards show a search finding you and an enquiry arriving.
- Side scroll-progress line (right edge) with the current section name
- Brand loader (plays once per session), frosted header with a green scroll-progress line, dark over violet panels, hides on scroll down
- Sections, in order: Hero, Client logo wall, Services, How we work, Work, Pricing, Free audit, Testimonials, Founder, FAQ, Final CTA, Contact, Footer
- Real proof: every work card is a browser frame holding a real full-page capture of the live site (auto-scrolls on hover), with a phone frame showing the real mobile capture where the site allows framing, and the client's real logo. The logo wall uses logos taken from each site.
- Motion, one rAF loop: Lenis smooth scroll (native fallback), bubble-trail cursor on a canvas (desktop only), hero spotlight, pinned process scene and pinned horizontal work gallery (desktop), project index with a floating preview, card tilt, magnetic buttons, count-ups, scramble eyebrows, footer fill.
- Motion is on by default; the Motion toggle in the footer and menu turns it off and is remembered per visitor.
- Brand: midnight violet `#251E45`, vivid green `#63B849`, soft lavender `#C9BCE8`, off-white `#FAF9FC`. Anton for display, Inter for body.

## Editing

Edit the source in `source/src/` (or the copy in `source/build/`), then build locally:

```bash
SITE_URL=http://localhost:8000 python3 source/build/build_site.py   # writes public/ and source/preview.html
python3 -m http.server 8000 -d public
```

Favicon PNGs are rendered from the logo only when you ask: `python3 source/build/build_site.py --icons` (needs Playwright).

`build_site.py` also holds the work-card copy, FAQ copy and icons. `process_assets.py` turned the raw browser captures into `source/static/assets/` (raw captures are not in the repo). The logo paths in `paths.json` were traced from `logo-uscale.png` with `trace.py` (needs `pip install potracer opencv-python scipy`).

## Contact form

Enquiries are emailed to uscalewithus@gmail.com through FormSubmit (no account, no backend). The first submission sends a one-time "Activate form" email to that inbox: click it once and every enquiry after that arrives as an email (reply-to is set to the visitor). If the service is ever unreachable, the form offers to send the same message on WhatsApp instead.
