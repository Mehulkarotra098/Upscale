# U Scale website

Single-page site for **U Scale**, Mehul Karotra's independent web design, development and digital marketing practice in Mumbai. Not an agency: clients contract with Mehul directly.

The site is generated by a small Python build (standard library only) into `public/`, which is what Vercel serves. Nothing generated is committed: every page, the sitemap, robots.txt and llms.txt are rebuilt on each deploy with the URL from the `SITE_URL` environment variable.

```
source/src/      page template, CSS, JS, testimonials
source/build/    build scripts, copy (work, FAQ, services, pricing), config.py (env settings)
source/static/   images and icons copied as-is (assets/, og-image.png, favicons)
api/             Vercel functions (one-line entry points): blog.js, img.js, admin.js
server/          blog + admin backend (see "Backend" below)
admin/           blog admin app (Preact + TipTap), bundled by admin/build.mjs into public/admin/
test/            unit tests (no database) and integration tests (real Postgres)
dev/server.mjs   local server that copies vercel.json routing (npm run dev, port 8787)
scripts/         build checks
public/          build output (git-ignored)
```

## Environment variables

| Variable | Purpose | Default |
|---|---|---|
| `SITE_URL` | Public origin used in canonical tags, Open Graph, JSON-LD, sitemap, robots.txt and llms.txt | `https://uscale.in` (`DEFAULT_SITE_URL` in `config.py`) |
| `SITE_INDEXABLE` | Force `1` (indexable) or `0` (noindex) | Indexable only when `VERCEL_ENV=production`, so preview deployments are `noindex` with a `Disallow: /` robots.txt |
| `OUTPUT_DIR` | Build output folder | `public` |
| `BUILD_DATE` | `lastmod` / `dateModified` date (YYYY-MM-DD) | Last git commit date, else today |
| `DATABASE_URL` | Postgres for the blog. Supabase project `uscale-blog`, **Transaction pooler** (port 6543), user `uscale_app.<project-ref>`. Tables are created automatically on first connect (schema `uscale`). | none: without it `/blog` shows a "coming soon" page and the admin shows a setup message |
| `SESSION_SECRET` | Signs admin login cookies and preview links. Any random string, 32+ characters. Changing it signs everyone out. | required for the admin |
| `ADMIN_EMAIL`, `ADMIN_PASSWORD` | First sign-in with these creates the owner account (only while no users exist). Change the password in Team & account afterwards. | |
| `ADMIN_NAME` | Display name of that first account | `Mehul Karotra` |
| `INDEXNOW_KEY` | Optional. Pings Bing/Yandex instantly on publish; key served at `/indexnow-key.txt` | off |
| `CRON_SECRET` | Optional. When set, only Vercel's cron (which sends it) can call the keep-alive ping | open |
| `AI_LOG_KEY` | Optional. Any long random string. Turns on the AI search log: `middleware.js` reports AI assistants, AI crawlers and visits from AI answers to `/api/blog?view=ai`, shown in Admin → AI search | off |

Set them in Vercel → Project → Settings → Environment Variables (Production and Preview). See `.env.example`.

## Blog and admin

- Write at **/admin** (sign in, then New post). Posts live at `/blog/<slug>`, categories at `/blog/category/<slug>`, RSS at `/blog/rss.xml`.
- Editor: headings, lists, quotes, tables, callout boxes (tip / note / warning / key number), call-to-action boxes, internal links (search your pages and posts) and external links (open in a new tab, optional nofollow / sponsored). Drop or paste images straight into the text.
- Images are resized in the browser to 1600px + 800px WebP, stored in the database and served from `/media/` with a one-year cache. Alt text is required.
- SEO panel: focus keyword, title and description with a Google preview, a live score with a checklist, internal link ideas, FAQ (FAQPage rich results), canonical and noindex.
- Each post gets BlogPosting, BreadcrumbList and FAQ structured data, Open Graph tags, a table of contents, related posts and a service CTA. `/sitemap.xml` is an index of `/sitemap-pages.xml` and `/sitemap-blog.xml` (with images).
- Changing the URL of a live post keeps the old one working (301). Revisions are saved automatically (last 25 per post). Drafts autosave. Future publish dates schedule the post.
- A daily Vercel cron calls `/api/blog?view=ping` so the free Supabase project never auto-pauses after 7 idle days.
- Local: `service postgresql start`, put `DATABASE_URL`, `SESSION_SECRET`, `ADMIN_EMAIL`, `ADMIN_PASSWORD` in `.env.local`, then `npm run build && npm run dev`.

## Backend

Plain Node (no framework) on Vercel functions in Mumbai, Postgres on Supabase. Layers, from the outside in:

```
api/*.js                     entry points, re-export a handler
server/blog/handler.js       public routes → render/ (listing, article, feeds, simple pages, shared parts), shell.js
server/admin/handler.js      admin API: method, sign-in, role and same-origin checks for every action
server/admin/actions/*.js    one file per area: session, dashboard, posts, media, categories, team
server/admin/input.js        turns untrusted input into clean values (or a 400 with a readable message)
server/media/                image URLs and the /media/ route
server/content/article.js    editor HTML → sanitized, SEO-ready article (headings, links, images, blocks, stats)
server/auth/                 passwords (scrypt), signed tokens (HMAC), sessions + sign-in rate limiting
server/repos/*.js            all SQL, one file per table group
server/db/                   connection pool (Supabase host failover) and versioned migrations
server/lib/                  errors, HTTP helpers, text helpers, structured logs
server/config.js             every setting and limit in one place
```

- **Errors**: expected failures throw `HttpError` (status + message safe to show). Anything else is logged as JSON and answered with a generic 500 or a friendly "back soon" page.
- **Database changes**: add a new entry to `server/db/migrations.js` (never edit a shipped one). It runs once, in a transaction, on the next cold start.
- **Security**: SQL is always parameterised; article HTML goes through an allowlist sanitizer; sessions are HttpOnly, Secure, SameSite=Strict signed cookies that a password change invalidates; admin writes need a same-origin custom header (blocks CSRF); sign-in is rate limited per account+IP and per IP using the platform's client IP; uploads are checked by their bytes, not their name.

## Tests and checks

```bash
npm run lint                # ESLint + Prettier
npm test                    # unit tests, no database needed
TEST_DATABASE_URL=postgresql://user:pass@localhost:5432/uscale_test npm run test:integration
npm run build               # also loads every function the way Vercel does (scripts/check-functions.mjs)
```

Integration tests run the real handlers against Postgres in a throwaway schema: sign-in and rate limits, CSRF and method checks, uploads, publishing, redirects, previews, feeds, the read counter and team permissions. GitHub Actions (`.github/workflows/ci.yml`) runs all of it on every pull request.

## Deploy

`vercel.json` holds everything: build command `npm run build` (the Python site build, then the admin bundle), output directory `public`, functions in Mumbai (`bom1`), blog routes, clean URLs, cache and security headers. Push to `main` and Vercel builds and deploys.

Other hosts (Netlify, Cloudflare Pages): same build command and output directory, and set `SITE_URL`.

## Editing

Edit the source in `source/src/` (or the copy in `source/build/`), then build locally:

```bash
SITE_URL=http://localhost:8000 python3 source/build/build_site.py   # writes public/ and source/preview.html
python3 -m http.server 8000 -d public
```

Favicon PNGs are rendered from the logo only when you ask: `python3 source/build/build_site.py --icons` (needs Playwright).

`build_site.py` also holds the work-card copy, FAQ copy and icons. `process_assets.py` turned the raw browser captures into `source/static/assets/` (raw captures are not in the repo). The logo paths in `paths.json` were traced from `logo-uscale.png` with `trace.py` (needs `pip install potracer opencv-python scipy`).
